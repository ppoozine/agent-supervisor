# HTTP API

The daemon (`agsv serve`) serves a JSON API under `/api`, at `http://127.0.0.1:8765/api` by
default (the port is `api_port` in the config file). The board uses this API and nothing else, so
anything the board does, a script can do too.

> **Not stable yet.** Until 1.0, endpoints, fields, and error codes may change in any minor release
> (0.3 to 0.4, and so on). Changes are listed in the release notes.

The daemon also serves interactive documentation generated by FastAPI at
<http://127.0.0.1:8765/api/docs>. It is handy for trying requests, and it describes request bodies
accurately, but it shows every response as "any object" and does not describe errors or the event
stream. This page is the reference for those.

## Access

There is no login. The daemon only listens on `127.0.0.1`, and it rejects, with `403 forbidden`:

- requests whose `Host` header is not `127.0.0.1`, `localhost`, or `::1` (with any port), which
  blocks DNS rebinding;
- requests with an `Origin` header that is not a page on one of those hosts, which blocks other
  websites open in your browser.

`curl` and scripts on the same machine work without any extra headers. Anyone who can run programs
on your machine can use the API.

## Conventions

- Request and response bodies are JSON. Send `Content-Type: application/json` with a body.
- Times are ISO 8601 strings in UTC with milliseconds, e.g. `"2026-11-22T02:37:16.794+00:00"`.
- Ids are integers. Fields that do not apply yet are `null` (e.g. `pr_number` before a pull request
  exists).
- Money is in US dollars. `cost_usd: null` means **unknown** (the agent does not report cost),
  never zero.
- Writes that start work answer as soon as the work is recorded; the work itself continues in the
  background. Follow it with the [live stream](#the-live-stream-sse) or by polling.

## Errors

Every error has the same shape:

```json
{"error": {"code": "run_already_active", "message": "task 3 already has an active run"}}
```

`code` is meant for programs and `message` for people. Codes:

| Status | `code` | When |
| --- | --- | --- |
| 403 | `forbidden` | The request was not addressed to, or not sent from, the local machine; see [Access](#access) |
| 404 | `not_found` | The project, task, or path does not exist |
| 405 | `method_not_allowed` | The path exists but not with this method |
| 409 | `project_exists` | The repository has already been added |
| 409 | `run_already_active` | The task already has a run in progress |
| 409 | `task_not_runnable` | The task is archived, or its pull request was merged or closed |
| 409 | `no_active_run` | Stop was requested but nothing is running |
| 409 | `process_still_running` | A run left over from before a restart could not be stopped because its agent process is still alive; stop that process and try again |
| 422 | `invalid_request` | The body is invalid (`message` names each field and problem), the path is not a git repository, or the agent type does not exist |
| 500 | `internal_error` | Anything unexpected, e.g. git failing while archiving |

## Projects

A project is a local git repository that tasks run against.

### `POST /api/projects`

Add a repository. Returns `201` with the project.

```json
{"repo_path": "~/code/my-app"}
```

| Field | Required | Meaning |
| --- | --- | --- |
| `repo_path` | yes | Path to the repository; `~` is expanded |
| `github_repo` | no | `owner/name`; detected from the `origin` remote when omitted |
| `default_branch` | no | The branch pull requests target; detected when omitted |
| `require_review` | no | When true, a card only moves to Ready to merge after an approving review. Default false |

Errors: `422 invalid_request` if the path is not a git repository, `409 project_exists` if it was
already added (its settings are left unchanged).

### `GET /api/projects`

All projects:

```json
[
  {
    "id": 1,
    "name": "my-app",
    "repo_path": "/Users/me/code/my-app",
    "github_repo": "me/my-app",
    "default_branch": "main",
    "require_review": false
  }
]
```

`github_repo` is `null` when none was given or detected; tasks can still run, but nothing can be
pushed.

## Tasks

A task is one piece of work: its own branch and worktree, one agent session, and at most one pull
request. Each time the agent runs for it is a **run**.

### The card

`GET /api/tasks` returns one card per task, and the other task endpoints return a card with more
fields. A card:

```json
{
  "id": 2,
  "project_id": 1,
  "title": "add a greeting",
  "agent_type": "example",
  "branch": "asv/task-2-add-a-greeting",
  "column": "In review",
  "label": "CI pending",
  "has_open_run": false,
  "pr_number": 14,
  "pr_state": "open",
  "head_sha": "3f2a9c1e...",
  "ci_state": "pending",
  "review_state": "none",
  "merge_state": "clean",
  "ci_fix_attempts": 0,
  "max_ci_fix_attempts": 3,
  "feedback_attempts": 0,
  "max_feedback_attempts": 5,
  "cost_usd": null,
  "tokens": 44,
  "usage_is_complete": true,
  "archived_at": null,
  "created_at": "2026-11-22T02:37:26.861+00:00",
  "updated_at": "2026-11-22T02:37:27.101+00:00"
}
```

| Field | Meaning |
| --- | --- |
| `column` | The board column: `Working`, `Needs you`, `In review`, `Ready to merge`, or `Archive`. Worked out from the other fields on every request, never stored |
| `label` | Why the card is in that column, for people (e.g. `Agent error`, `CI failed`). The wording may change; use the other fields in programs |
| `has_open_run` | Whether a run is in progress |
| `branch` | The task's branch; `null` until the first run has prepared it |
| `pr_number`, `pr_state` | The pull request, once opened; `pr_state` is `open`, `merged`, or `closed` |
| `head_sha` | The latest commit of the pull request as last seen on GitHub |
| `ci_state` | `none`, `pending`, `passed`, or `failed`: all CI checks on `head_sha` combined |
| `review_state` | `none`, `approved`, or `changes_requested` |
| `merge_state` | `unknown`, `clean`, or `conflicting` (with the base branch) |
| `ci_fix_attempts`, `max_ci_fix_attempts` | Automatic fixes used so far (failed CI and merge conflicts together) and the most allowed |
| `feedback_attempts`, `max_feedback_attempts` | Rounds of PR comments passed to the agent automatically so far, and the most allowed |
| `cost_usd` | Money spent since the last time a person stepped in (opening the task or sending a message); `null` if the agent does not report cost |
| `tokens` | Tokens used over the same period |
| `usage_is_complete` | False when some run's usage is unknown (e.g. it was stopped), so `cost_usd` and `tokens` are lower than the real figures |
| `archived_at` | When the task was archived, or `null` |

GitHub fields (`pr_state`, `head_sha`, `ci_state`, `review_state`, `merge_state`) are refreshed
by polling, every 30 seconds by default.

### Task detail

`POST /api/tasks`, `GET /api/tasks/{id}`, and the task actions below return the card plus:

| Field | Meaning |
| --- | --- |
| `prompt` | The instructions the task was opened with |
| `model` | The model asked for, or `null` for the agent's default |
| `session_id` | The agent session that later runs continue |
| `worktree_path` | The task's worktree on disk; `null` before the first run prepares it. Kept after archiving, although the directory is removed |
| `tokens_in`, `tokens_out` | Token totals over all runs of the task |
| `runs` | Every run of the task, oldest first |

A run:

```json
{
  "id": 2,
  "task_id": 2,
  "trigger": "initial",
  "input_text": "add a greeting",
  "source_head_sha": null,
  "started_at": "2026-11-22T02:37:26.861+00:00",
  "ended_at": "2026-11-22T02:37:27.271+00:00",
  "exit_status": "success",
  "tokens_in": 4,
  "tokens_out": 40,
  "cost_usd": null
}
```

| Field | Meaning |
| --- | --- |
| `trigger` | Why it ran: `initial`, `user_message`, `ci_failure`, `review_feedback`, or `merge_conflict` |
| `input_text` | The instructions the agent was given |
| `source_head_sha` | For automatic runs, the commit that triggered it |
| `ended_at`, `exit_status` | `null` while running. Then `success`, `error`, `stopped`, `limit_reached` (a turn, budget, or time limit), or `interrupted` (the daemon stopped while it ran) |
| `tokens_in`, `tokens_out`, `cost_usd` | This run's usage; `null` when unknown |

### `POST /api/tasks`

Open a task and start its first run. Returns `201` with the task detail as soon as the task exists;
the worktree is prepared and the agent runs in the background.

```json
{"project_id": 1, "prompt": "Add a /health endpoint that returns 200", "agent_type": "claude_code"}
```

| Field | Required | Meaning |
| --- | --- | --- |
| `project_id` | yes | The project to work in |
| `prompt` | yes | The instructions for the agent |
| `title` | no | Shown on the card; defaults to the first 60 characters of `prompt` |
| `agent_type` | no | Which agent; see [`GET /api/agents`](#get-apiagents). Default `claude_code` |
| `model` | no | Passed to the agent as is; `null` for its default |

Errors: `404 not_found` for an unknown project, `422 invalid_request` for an unknown agent type.
The task is opened even if the agent is not usable at the moment; the run then ends with an error.

### `GET /api/tasks`

All cards, including archived ones, in the order the tasks were opened. `?project_id=1` limits them to one project.

### `GET /api/tasks/{id}`

The task detail.

### `POST /api/tasks/{id}/messages`

Send a follow-up instruction to the task's agent session. Starts a new run and returns `201` with
the task detail.

```json
{"text": "Also add a test for it"}
```

A message also resets the task's cost and token count and its automatic fix attempts: a person
stepping in grants a fresh budget, so messages are never refused for being over budget.

Errors: `409 run_already_active` while a run is in progress (stop it first), `409
task_not_runnable` if the task is archived or its pull request was merged or closed.

### `POST /api/tasks/{id}/stop`

Stop the run in progress. Answers only after the agent has stopped and the run has ended, so it
can take a few seconds. Returns the task detail. The work so far stays in the worktree and nothing
is pushed; nothing runs automatically afterwards until a person steps in.

Errors: `409 no_active_run` if nothing is running; `409 process_still_running` for a run left over
from before a restart whose agent process could not be stopped.

### `POST /api/tasks/{id}/archive`

Archive the task: commit any uncommitted changes to the task's branch (without pushing), remove
its worktree, and move the card to Archive. The branch and the pull request are left as they are.
Returns the task detail. Archived tasks cannot run again.

Errors: `409 run_already_active` while a run is in progress, `409 task_not_runnable` if already
archived.

### `GET /api/tasks/{id}/diff`

What the task's branch changes compared with the base branch:

```json
{"diff": "diff --git a/app.py b/app.py\n...", "is_truncated": false, "base_branch": "main"}
```

`diff` is `git diff` output, empty before the task has a branch. Diffs over 400,000 characters
are cut at the last whole line and `is_truncated` is true.

## Events (the audit log)

Everything that happens to a task is recorded as an event and never changed or deleted
afterwards: what the agent did, pushes, pull requests, CI and review changes, comments, and how
each run ended.

```json
{
  "id": 5,
  "task_id": 2,
  "run_id": 2,
  "ts": "2026-11-22T02:37:27.102+00:00",
  "type": "command",
  "payload": {"phase": "started", "tool_use_id": "79cc4392", "tool": "shell", "command": "ls"}
}
```

`run_id` is `null` for events that do not belong to a run, such as CI changes found by polling.
The `payload` depends on `type`:

| `type` | Written by | Payload |
| --- | --- | --- |
| `session_started` | The agent's adapter | `session_id`, `process_marker` |
| `agent_message` | The agent's adapter | `kind` (`message`, `reasoning`, or `plan`), `text` |
| `command` | The agent's adapter | `phase` (`started` or `finished`), `tool_use_id`, `tool`, `command`; when finished, `output`, `exit_code`, `is_error` |
| `tool_call` | The agent's adapter | `phase`, `tool_use_id`, `tool`, `input`; when finished, `is_error` and any result |
| `permission_denied` | The agent's adapter | `tool`, `input`, `reason` |
| `pushed` | agent-supervisor | `branch`, `head_sha`; `forced` and `replaced_sha` when the push overwrote a commit it had pushed before |
| `pr_opened` | agent-supervisor | `number`, `url` |
| `ci_status` | Polling | `pr_state`, `head_sha`, `ci_state`, `review_state`, `merge_state`, `pr_number`; written only when one of them changes |
| `review_comment` | Polling | `github_id`, `kind` (`comment`, `review`, or `inline_comment`), `author`, `author_association` (GitHub's relation of the author to the repo, e.g. `OWNER`, `NONE`), `body`, `path`, `line`, `url`, `review_state`, `created_at`; `ignored` holds the reason when the comment is not passed to the agent: `bot`, `untrusted_author`, `empty`, or `not_a_change_request` |
| `state_change` | agent-supervisor | `change` (`run_ended`), `exit_status`, `detail`, `usage_raw` |

Payloads written by adapters may carry extra fields, and each agent fills them in its own way. The
[adapter guide](adapters.md#events) describes them in detail.

### `GET /api/tasks/{id}/events`

The task's events, oldest first, a page at a time:

```json
{"events": [ ... ], "next_after": 120}
```

| Query | Meaning |
| --- | --- |
| `after` | Only events with an id above this. Default 0 |
| `limit` | Page size, 1 to 500. Default 100 |
| `type` | Only events of this type |

`next_after` is the `after` for the next page, or `null` when this was the last page. To follow a
task as it runs, use the [live stream](#the-live-stream-sse) instead of polling this.

## Agents and setup

### `GET /api/agents`

The agents this daemon can run, built in and installed:

```json
[
  {"agent_type": "claude_code", "display_name": "Claude Code", "usable": true, "reports_cost": true},
  {"agent_type": "codex", "display_name": "Codex", "usable": true, "reports_cost": false}
]
```

`agent_type` is what `POST /api/tasks` takes. `usable` is as of the last check (see below).
`reports_cost` false means its tasks show tokens instead of money.

### `GET /api/setup`

Whether each agent and `gh` can be used, as of the last check. The daemon checks when it starts.

```json
{
  "checked_at": "2026-11-22T02:37:08.290+00:00",
  "agents": [
    {
      "agent_type": "codex",
      "display_name": "Codex",
      "usable": true,
      "installed": true,
      "version": "0.167.0",
      "auth": "subscription",
      "auth_label": "ChatGPT",
      "detail": null,
      "fix": [],
      "notice": null
    }
  ],
  "github": {"usable": true, "installed": true, "version": "2.101.0", "auth": "account", "...": "..."}
}
```

| Field | Meaning |
| --- | --- |
| `usable` | Installed and signed in |
| `installed`, `version` | Whether it can be run, and its version if known |
| `auth` | How it is signed in: `api_key`, `subscription`, `cloud_provider`, `account`, `other`, or `none` |
| `auth_label` | The same, for people, e.g. `"claude.ai (max)"`. Never contains a credential |
| `detail` | Why it cannot be used, when it cannot |
| `fix` | Commands to run in a terminal to fix it |
| `notice` | Something worth knowing even though it can be used |

Signed in means credentials are configured; whether they are valid only shows when the agent
runs.

### `POST /api/setup/check`

Check everything again, e.g. after signing in from a terminal, and return the result in the same
shape. Takes a few seconds: it asks GitHub whether `gh` is signed in.

## Usage

### `GET /api/usage`

Token and cost totals, per task and overall. `?project_id=1` limits them to one project.

```json
{
  "cost_usd": 1.82,
  "tokens_in": 120400,
  "tokens_out": 18800,
  "has_unknown_cost": true,
  "usage_is_complete": true,
  "tasks": [
    {
      "task_id": 2,
      "title": "add a greeting",
      "agent_type": "codex",
      "cost_usd": null,
      "tokens_in": 4,
      "tokens_out": 40,
      "usage_is_complete": true
    }
  ]
}
```

A task's `cost_usd` and `usage_is_complete` cover the period since a person last stepped in, as on
the card; `tokens_in` and `tokens_out` cover all its runs. The overall `cost_usd` only adds up
tasks that report cost; `has_unknown_cost` is true when some tasks do not.

## Settings

### `GET /api/config`

The limits and permission policy the daemon is running with. Read-only: to change them, create or
edit the file named in `config_path` (it may not exist yet; the defaults apply) and restart
`agsv serve`.

```json
{
  "config_path": "/Users/you/.agent-supervisor/config.toml",
  "limits": {
    "task_cost_limit_usd": 5.0,
    "task_token_limit": 20000000,
    "max_turns_per_run": 50,
    "run_timeout_seconds": 1800.0,
    "max_ci_fix_attempts": 3,
    "max_feedback_attempts": 5
  },
  "poll_interval_seconds": 30.0,
  "notify_needs_you": true,
  "permission": {
    "sandbox_level": "workspace-write",
    "allow_network": true,
    "tool_rules": {
      "allowed_tools": ["Read", "Glob", "Grep", "Write", "Edit", "MultiEdit", "Bash", "TodoWrite"],
      "denied_commands": ["git push", "gh", "sudo", "rm -rf /"]
    }
  }
}
```

`max_ci_fix_attempts` and `max_feedback_attempts` are built in, not settings. `tool_rules` is passed
to the adapters as is; each adapter reads the keys it knows. Other settings in the file, such as the
data directory and the port, are not included.

## The live stream (SSE)

`GET /api/stream` is a [Server-Sent Events](https://html.spec.whatwg.org/multipage/server-sent-events.html)
stream of everything that changes, for all tasks. In a browser, use `EventSource`:

```js
const stream = new EventSource('/api/stream')
stream.addEventListener('event', (message) => {
  const event = JSON.parse(message.data)   // an audit log event, as in GET /api/tasks/{id}/events
})
stream.addEventListener('task', (message) => {
  const card = JSON.parse(message.data)    // the latest card, as in GET /api/tasks
})
```

From a terminal: `curl -N http://127.0.0.1:8765/api/stream`.

There are two kinds of messages:

```text
: connected

event: task
data: {"id": 2, "project_id": 1, "title": "add a greeting", "column": "Working", ...}

id: 5
event: event
data: {"id": 5, "task_id": 2, "run_id": 2, "type": "command", "payload": {...}, ...}
```

- **`event`**: a new audit log event. The SSE `id` is the event's id.
- **`task`**: a card changed (column, label, CI state, usage, ...). It carries the whole card.
  Cards have no id and are not replayed.

Lines starting with `:` are comments: one when the connection opens, and a ping every 15 seconds
or so while nothing happens. Ignore them.

### Reconnecting

The stream ends when the daemon shuts down, or when a client reads too slowly to keep up. Reconnect
and send the id of the last `event` you received in the `Last-Event-ID` header; `EventSource` does
both by itself. The events after that id are sent first, then live messages, without duplicates.

Cards are not replayed, so after reconnecting, fetch `GET /api/tasks` again to catch up on them.
Without `Last-Event-ID`, only changes from that point on are sent.
