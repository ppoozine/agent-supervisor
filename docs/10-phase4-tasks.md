# 10 · 階段 4 任務單

最後更新：2026-11-20

階段 4「開源準備」的八個任務，對應 `01-roadmap.md` 的階段 4。規劃的過程與每個決定的理由見 `09-open-source-plan.md`。

這個階段的目標是：**一個不認識作者的開發者，能把它裝起來、看得懂、接上自己的 agent。** 做完把 repo 設成公開，發 `0.3.0`。

做法：**一次做一個任務，合併之後才開始下一個**（`03-decisions.md` 第 150 筆）。每個任務一個 branch、一個 PR，開始前先提計畫、確認後再動手。這個階段有幾個任務的變更很大，不像階段 3 那樣把 PR 疊在一起。

順序的理由：CI 最先，後面每個任務都靠它把關；英文化要早，之後新寫的程式直接用英文；行為的修正排在新功能之前；對外的文件最後寫，那時要描述的東西才都定下來了。

## 任務 11 · 這個 repo 的 CI

```
請先讀 CLAUDE.md 與 docs/ 下的所有文件。

替這個 repo 加上 CI。

範圍：
1. GitHub Actions：每個 PR 與 push 到 main 時執行
2. 後端：uv sync、ruff check、ruff format --check、pytest
3. 前端：npm ci、npm test、npm run build
4. 在 macOS 與 Linux 上都跑
5. 測試不得真的啟動 agent，也不得打 GitHub；CI 上沒有登入任何
   帳號，確認現有的測試在這種環境下都能跑
6. Linux 上失敗的測試先全部列出來給我看，不要在這個任務裡修
   （那是任務 12）；要讓 CI 能合併的話，先把 Linux 設成允許
   失敗，並寫明哪些測試失敗
7. 在 README 加上 CI 狀態的徽章

不要做：自動發版、自動部署、程式碼覆蓋率的門檻。
```

**我要驗證的事**
- [ ] 開一個 PR，GitHub 上看得到檢查在跑，macOS 的全部通過
- [ ] 故意讓一個測試失敗，CI 變紅；改回來後變綠
- [ ] Linux 上哪些測試失敗有一份清單

   docs/ 下的設計文件用繁體中文
8. 怎麼分批、怎麼讓我容易檢查，先向我提出

不要做：翻譯 docs/ 下的文件、改名、重構。

## 任務 14 · 修掉會卡住的五項

```
請先讀 CLAUDE.md 與 docs/ 下的所有文件。

修掉五個會讓任務卡住、只能人工處理的問題
（09-open-source-plan.md 的現況盤點）。

範圍：
1. PR 被關閉後又重新開啟：工具要能發現，任務恢復成可以操作

   手動結案的方法

   提出
6. 每一項都要有重現問題的測試

每一項的做法先向我提出，確認後再動手。五項可以分成幾個 PR
由你提出。

不要做：盤點裡「顯示或操作不順」與「任務變多之後」的項目。
```

**我要驗證的事**

## 任務 15 · Agent 設定頁與偵測

```
請先讀 CLAUDE.md 與 docs/ 下的所有文件。

讓使用者知道自己能用哪些 agent、缺了什麼
（03-decisions.md 第 140、141 筆）。

範圍：
1. 每個 adapter 多一個「檢查自己能不能用」的方法：有沒有
   安裝、版本、有沒有登入、用的是哪一種登入。介面的形狀先
   向我提出；Runner 仍然不得出現任何 agent 專屬的字串
2. gh 也要檢查（有沒有安裝、有沒有登入）
3. 新的端點回報每一種 agent 與 gh 的狀態
4. 介面上的設定頁：列出每一種 agent 的狀態；不能用的寫明
   要在 terminal 執行什麼
5. 開任務的表單只列出可以用的 agent
6. Claude Code：預設引導使用者設定 ANTHROPIC_API_KEY；偵測到
   用的是訂閱登入時顯示一段說明（官方文件的條文、它沒有講
   清楚的地方、由使用者自己判斷），不擋
7. 工具本身不處理任何憑證：不做登入流程，不儲存、不顯示
   API key 或 token
8. daemon 啟動時把檢查的結果寫進 log；沒有任何 agent 可用時
   的行為先向我提出
9. 檢查不能真的花用量；怎麼判斷「有沒有登入」先查各家的
   文件並實測，記進調查筆記

直接打 endpoint 的 agent。
```

- [ ] 把其中一個 CLI 暫時移出 PATH，設定頁顯示它沒有安裝與該怎麼做，開任務的表單裡沒有它

```
請先讀 CLAUDE.md 與 docs/ 下的所有文件。

（03-decisions.md 第 142 筆）。

   的意思、事件的型別與 payload、capabilities 怎麼填、中止時
   必須做到什麼、用量怎麼回報、常見的錯誤

6. 照著指南從頭寫一個 adapter 來驗證指南本身，把卡住的地方
   修進指南

```

- [ ] 只看指南、不看現有的兩個 adapter，能寫出一個可以跑的 adapter
- [ ] 範例 adapter 在沒有任何 agent 帳號的環境下，能讓一個任務走完整個流程
